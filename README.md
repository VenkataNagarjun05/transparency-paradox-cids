# The transparency paradox in collaborative intrusion detection

Code, run records and analysis scripts for the paper

> A. Venkata Nagarjun and Sujatha Rajkumar. *The Transparency Paradox in Collaborative Intrusion Detection: Adaptive Attacks on
> Smart-Contract-Governed Federated Learning with Post-Quantum Signatures in Cloud Networks.* Manuscript under review, 2026.

When a federated intrusion detector puts its acceptance rule in a smart contract, every tenant can read that rule, including the
malicious ones. This repository holds everything we used to test what such tenants can do with it:

- a federated learning simulator with twelve acceptance rules and six attackers, among them an attacker that runs a private copy of
  the published rule and optimises its update against it;
- a Solidity contract with commit-reveal, a block-hash beacon, committee attestation and slashing;
- the post-quantum layer (ML-DSA signatures on commitments, ML-KEM envelopes for updates, via liboqs);
- the four Kaggle notebooks that produced the results, the pre-registrations written before each run, and the raw run records;
- the script that regenerates every table, figure and number in the paper.

## Repository layout

| Path | What is there |
|---|---|
| `qbfl/` | Python package. `data.py` loads the data and builds tenants, `model.py` is the batched MLP, `defenses.py` has the acceptance rules, `attacks.py` the attackers, `fl.py` the training loop, `accountability.py` the slashing rules, `pqc.py` the post-quantum layer, `grid.py` the experiment grids and `analysis.py` the statistics helpers |
| `chain/` | `contracts/CIDSContract.sol`, the Hardhat config, gas measurement (`measure_gas.py`), the 40-round end-to-end run (`integration.py`) and the contract tests (`test_contract.py`) |
| `notebooks/` | `quantum_bc_fl_cids_R1.ipynb` to `_R4.ipynb`, the Kaggle notebooks behind every result in the paper (generated by `tools/build_replication.py`) |
| `docs/` | Pre-registrations `PREREG_REPLICATION.md`, `PREREG_R3.md` and `PREREG_R4.md`, and `RESULTS_MAP.md`, which links each headline claim to its test, raw records and analysis function |
| `results/kaggle/r1` to `r4` | Run records of the four pre-registered experiments: 8,455 federated runs and 25 reference models, one JSON line per run. Checksums are in `results/kaggle/SHA256SUMS_replication` |
| `results/*.json` | Measured gas per operation and per round, the end-to-end chain run, and the synthetic check of the slashing e-processes |
| `paper/` | `numbers.json` (every number quoted in the paper) and the generated tables as CSV |
| `tools/` | `make_tables.py` rebuilds tables, figures and `numbers.json`; `check_numbers.py` checks the manuscript against `numbers.json`; `audit_tables.py` recomputes the key tables independently; `mock_run_notebook.py` dry-runs a notebook on fake data; `test_eprocess.py` checks the slashing rules |
| `tests/` | Unit tests for the package |

## Getting started

```bash
git clone https://github.com/VenkataNagarjun05/transparency-paradox-cids.git
cd transparency-paradox-cids
pip install -r requirements.txt
```

The R1 bundle is larger than GitHub's web upload limit, so it is stored in two pieces. Join them once after cloning:

```bash
cat results/kaggle/r1/results_R1_bundle.zip.part-* > results/kaggle/r1/results_R1_bundle.zip
shasum -a 256 results/kaggle/r1/results_R1_bundle.zip   # compare with results/kaggle/SHA256SUMS_replication
```

## Reproducing the paper

**Tables, figures and numbers (CPU, a few seconds).** These come straight from the archived run records:

```bash
python3 tools/make_tables.py
python3 tools/check_numbers.py
```

**Experiments (GPU).** Import `notebooks/quantum_bc_fl_cids_R1.ipynb` into Kaggle (GPU T4 x2, internet on) and run all cells. The
notebook downloads the four NetFlow-v2 datasets with `kagglehub` and writes `results_R1_bundle.zip`; it takes roughly 7 GPU hours.
R2 needs the Kubernetes dataset `redamorsli/kube-ids0` added as a notebook input (about 5 GPU hours). R3 and R4 run the same way. Each
finished run is appended as one JSON line, so an interrupted session picks up where it stopped.

**Smart contract (CPU).**

```bash
cd chain && npm install && npx hardhat compile
python3 -m pytest -q test_contract.py     # 11 contract tests on a local EVM
npx hardhat node &                        # then, in a second shell:
python3 measure_gas.py && python3 integration.py
```

**Tests.**

```bash
python3 -m pytest -q tests
python3 tools/test_eprocess.py
```

## Data

All datasets are public and none are redistributed here. We use the NetFlow-v2 versions of UNSW-NB15, CSE-CIC-IDS2018, ToN-IoT and
BoT-IoT (Kaggle mirrors `dhoogla/nfunswnb15v2`, `dhoogla/nfcsecicids2018v2`, `dhoogla/nftoniotv2` and `dhoogla/nfbotiotv2`, licence
CC BY-NC-SA 4.0) and the Kubernetes intrusion-detection dataset `redamorsli/kube-ids0`.
